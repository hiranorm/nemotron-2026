# Postmortem — 自陣 0.852 と金圏 0.920 の間に何があったか

## 事実

| | 自陣 | 金圏（1st） |
|---|---|---|
| private | **0.852 → 401位 / 4,182 = 🥉銅メダル** | 0.920（1位） |
| public | 0.856（1672位）→ **private で +1271** | 0.912 |
| 提出数 | 20 | — |
| 投入した計算 | Colab / Kaggle の範囲、実質数十時間 | RTX PRO 6000 1枚で 170h、8.9 億トークン |
| 触った層 | **公開 0.85 ノートのレシピ（lr schedule / epochs / データ差し替え）** | ソルバ・トレース設計・合成データ生成 |

**結果は銅メダル。**ただし 0.852 の同点ブロック（348位〜600位以降）の中で銅の境界（418位）が引かれており、
**401位＝マージン 17位**。スコアの上では「同点内で運が良かった」側にいた。

**+1問（0.852 → 0.856）で銀圏（209位）が射程だった**（0.856 は private 177〜347位）。
金圏（0.868 = 16位〜）までは +4問。→ 内訳は [final-leaderboard](research/final-leaderboard.md)。

## 何が本当のレバーだったか

上位 18 チームの writeup を読んだ結論は明快で、**このコンペのレバーは学習側にほぼ無かった**。

- LoRA 設定はほぼ全チーム同じ（r=32 / α=32 / lr 2e-4 / 1 epoch / target に lm_head）。自陣の設定もこれと同じだった。
- 差は **(1) ソルバの仮説クラス**、**(2) トレースの可学習性**、**(3) 7,680 トークン予算内への収め方**。
  bit manipulation だけで 85% → 99% の差があり、これが数十問ぶんに相当する。
- 自陣は (1)(2)(3) をどれも触っていない。**「公開ノートのパラメータ探索」という層で 20 提出を使い切った。**

**child-exp006（lr schedule を受賞流に）と child-exp007（受賞データに差し替え）が両方外れたのは偶然ではない。**
両方とも「上位が勝った層」ではない層の介入だった。

## child-exp007（-0.01）の再解釈

当時の仮説は GUARDRAILS.md に 3 つ書いてある（量律速 / セット効果 / 私的版データの品質劣化）。
終了後の情報から、**4 番目の仮説がいちばん確度が高い**:

> **ソルバの正解率とトレースの可学習性は別の量**であり、正解率の高いデータに差し替えても LB は下がりうる。

根拠:

- discussion 697491 の同型事例: 合成データの解答率を 87.7% → 95.8% に上げて LB は 0.85 → 0.82〜0.84 に**下がった**。
  診断は (a) 難カテゴリのトレースが base model の logprob で見て追いにくい、(b) 難カテゴリの oversample で基礎カテゴリを上書き。
- 4th・18th・9th が独立に同じ主張をしている（「CoT はソルバが動いた記録ではなく学習可能な軌跡」）。
- 上位は**データを差し替えるとき、必ずトレース形式も一緒に設計している**。データだけの移植は誰もやっていない。

→ 一般化した規則は [method/learnable-trace](method/learnable-trace.md) に置いた。

## 測り方の失敗（ここがいちばん重い）

自陣はローカル検証を持たず、**public LB だけで判定していた**。終了後に分かったこと:

1. **public 0.860 に 1,084 チームが積み上がっていた**。飽和したプラトーの上で ±0.01 を読んでいた。
2. **1 提出の測定ノイズが 0.01 前後ある**（vLLM の推論が temperature=0 でも非決定的。ホストも参加者も明言）。
   自陣の 20 提出のスコア差の多くは**判定不能な差**だった可能性がある。
3. **public と private は 0.86 付近で順序が入れ替わる**。3rd の「public 0.85 の提出が private 0.90」、
   10th の「public 0.860 / private 0.880 が最良」、18th の「public 0.864 / private 0.880 を選べなかった」。
4. **ホストが期間中に明言していた**（`discussion/698106`, CPMP）:
   「adapter の評価はローカル CV に頼るべき。public LB に頼るのは overfitting のレシピだ。大事なのは private だ。」

**同じ失敗を 18 位のチーム（金メダル）も自分から書いている**ので、これは自陣固有の弱さではなく、
このコンペの構造的な罠だった。ただし上位 10 チームは全員この罠を回避していた。回避の型は 3 つ:

| 型 | 誰 | 中身 |
|---|---|---|
| 合成データで学習し **train.csv 全件を検証に回す** | 5th, 6th | 検証集合が 10 倍になる。「train で学習して train で検証」の自己参照を断つ |
| 層化ホールドアウト（10%, augment 由来のリークも除去） | 3rd, 9th, 10th | private をよく追随した（public は追随しない） |
| **ドメイン別 LB プロービング** | 6th | 対象ドメイン以外を `\boxed{DUMMY}` に学習させて提出し、public から単一ドメインの信号だけ取り出す |

加えて全員が**提出せずに測れる代理指標**を持っていた（オラクル解答率、perfect trace rate、first token divergence、logprob）。

## ドキュメント側の誤り（終了後に判明）

- **評価指標の記述が誤っていた。** `research/competition_overview.md` と `RESULTS.md` は
  「pass@1 (maj@64)」「maj@64 は不可侵」と書いているが、実際の評価は
  **temperature=0.0 / top_p=1.0 / max_tokens=7680 の 1 パス greedy 生成**だった（1st place writeup の記述、
  および `discussion/698106` の非決定性に関するやり取り）。AIMO-2 の先例から推測した前提を、**一次情報で検証せずに固定していた。**
  - 実害: 「デコードは触れない、レバーは adapter だけ」という結論自体は正しかったので、方針は狂っていない。
    ただし **max_tokens=7680 がトレース設計の主制約である**という最重要事実が、記録のどこにも書かれていなかった。
    上位はここを起点に HEX 圧縮・探索分割をやっている。
- **指標の改訂を追えていなかった。** 2026-05 中旬に答案抽出（`}` を含む答え）の修正が入り、**再スコアは行われなかった**
  （`discussion/698106`）。つまり自陣の最良提出（4/29・5/1）は旧メトリクスでの採点で、
  6/15 締切時点の他チームと同じ物差しではない可能性がある。改訂後に再提出はしていない。

## 撤退判断（2026-06-02）の事後評価

**判断そのものは妥当で、しかも結果として銅メダルを持って帰れている。** 主戦場を ROGII に置き、
こちらを軽量打ち切りにする方針は、上位に必要だった投資量（1st: 170 GPU時間 + 生成器の逆算、
2nd: 4×A100 で 11h + 独自インフラ）から見て、片手で戦って届く距離ではなかった。
**放置した adapter が private 401位（銅）に残ったのは、撤退の仕方が正しかった**ということでもある
（動くものを最後に置いてから降りている）。

問題は判断ではなく**判断の材料**だった:

- 「0.85 で停滞」を根拠に撤退したが、その 0.85 は**飽和した public LB の値**で、private の位置は測っていなかった。
  実際には **public 1672位 → private 401位（+1271）**。「1672位で停滞」に見えていたものは銅圏の実力だった。
  **停滞の判定に使った物差しが、そもそも順位を測れていなかった。**
- 銀圏は **+1問**の距離にあった（0.856 = private 177〜347位、銀の境界は 209位）。
  「レシピ探索の外側に 3問ある」と思って降りたが、実際の距離はもっと近かった。
  ただし**その1問がレシピ探索で取れたかは別問題**で、上位が勝った層（ソルバ・トレース）に入る必要はやはりあった。
- 「本命 2 本（c006/c007）が外れた」を根拠にしたが、2 本とも**当たる可能性が構造的に低い層**の介入だった。
  外れたこと自体は情報量が小さい。
- 撤退の直前に着手した TASK-004（カテゴリ別診断）は**正しい方向だった**が、実行前に打ち切った。
  上位の全員がまずこれ（どのカテゴリが弱いか、オラクルとモデルの差はどこか）をやっている。

→ 教訓は「撤退するな」ではなく、**「撤退は測ってから決める。測る道具は撤退候補になった時点でもう手遅れなので、最初に作る」**。
